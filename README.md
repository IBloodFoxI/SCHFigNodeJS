# figura-backend

Свой бэкенд Figura отдельным сервисом в Docker. Node 22, TypeScript, одна
runtime-зависимость (`ws`).

Даёт то, чего нет у официального бэкенда:

* **аватары работают у игроков без лицензии** — личность подтверждается входом
  на Minecraft-сервер, а не сессионным сервером Mojang;
* **лимит веса аватара задаётся вами** вместо жёстких 100 КБ;
* всё хранится у вас, ни один аватар не уходит на сторонний сервис;
* бэкенд переживает рестарты игрового сервера.

## Из чего состоит система

```
FiguraLink (плагин Paper)              figura-backend (этот сервис)
──────────────────────────             ────────────────────────────
игрок зашёл и прошёл nLogin            /api/*  и  /ws на одном порту
  ↓                                    аватары, профили, кэш ресурсов
подписать HMAC-токен  ─── общий ────→  проверить подпись
отправить figura:backend    секрет     лимиты читаются прямо из токена
```

Плюс **форк клиента SCHFigura** — без него обычная Figura для пиратки не
работает в принципе: она требует ответа сессионного сервера Mojang и отбрасывает
offline-UUID.

Между плагином и сервисом нет ни базы, ни сети, ни требований к порядку
запуска — только совпадающий секрет.

## Запуск

Собирать на сервере ничего не надо — образ публикует GitHub Action в GHCR.

```bash
cp .env.example .env
```

Заполнить `FIGURA_SECRET` (то же значение, что в `config.yml` плагина
FiguraLink) и проверить `FIGURA_DOMAIN`. Затем:

```bash
docker compose up -d
```

Обновление:

```bash
docker compose pull && docker compose up -d
```

### Traefik

Контейнер порты наружу не публикует — он живёт в сети `proxy` и выставляется
метками. Сертификат выпускается на основном уровне Traefik, поэтому здесь только
роутер:

```yaml
labels:
  - "traefik.enable=true"
  - "traefik.docker.network=proxy"
  - "traefik.http.routers.figura.rule=Host(`${FIGURA_DOMAIN}`)"
  - "traefik.http.routers.figura.entrypoints=${TRAEFIK_ENTRYPOINT:-websecure}"
  - "traefik.http.routers.figura.tls=true"
  - "traefik.http.services.figura.loadbalancer.server.port=8080"
```

Вебсокет Traefik проксирует сам, включать ничего не нужно. Единственное, за чем
стоит следить, — таймаут простоя на entrypoint: держите
`FIGURA_WS_KEEPALIVE_SECONDS` заметно ниже него.

Если сеть `proxy` создаётся стеком основного Traefik, а не этим compose,
раскомментируйте `external: true` в секции `networks`.

TLS обязателен: клиент Figura ходит **только** по `https://` и `wss://` — схемы
зашиты в код мода, и самоподписанный сертификат тоже не подойдёт.

## Настройки

Все через переменные окружения, полный список с комментариями — в `.env.example`.
Что стоит понимать:

| Переменная | Смысл |
| --- | --- |
| `FIGURA_SECRET` | обязательная; общий секрет с плагином |
| `FIGURA_DATA_DIR` | аватары, профили, кэш ресурсов; volume из compose |
| `FIGURA_MAX_AVATAR_SIZE_CEILING` | **не** рабочий лимит, а предохранитель |
| `FIGURA_VERSION_RELEASE` | должна совпадать с `mod_version` форка |
| `FIGURA_WS_KEEPALIVE_SECONDS` | за Cloudflare не выключать |

**Лимит веса аватара задаётся в плагине, а не здесь.** Он подписывается внутрь
токена, потому что только плагин знает про группы прав. Переменная выше — потолок
на случай сломанного или устаревшего плагина; ставьте её заметно выше и забудьте.

## Место на диске

Перезаливка аватара место **не** занимает: клиент всегда шлёт его под статичным
id `avatar`, файл перезаписывается поверх. На игрока приходится ровно один файл
плюс профиль на 165 байт.

Растёт только одно — аватары игроков, которые перестали заходить. Для них есть
автоочистка:

```env
FIGURA_CLEANUP_ENABLED=true
FIGURA_CLEANUP_INACTIVE_DAYS=90
FIGURA_CLEANUP_INTERVAL_HOURS=24
```

Активность считается **по обращениям с токеном этого игрока**, а не по
скачиваниям его аватара: клиенты кэшируют аватары по хэшу, и файл активного
игрока может неделями никем не запрашиваться. Отметка идёт через mtime файла, не
чаще раза в час на игрока.

Заодно сносятся осиротевшие `*.tmp` — от процесса, убитого посреди записи. Это
делается и при каждом старте сервиса.

## Администрирование

Включается непустым `FIGURA_ADMIN_TOKEN`. Пустой — маршруты отвечают 404, как
будто их нет. Это отдельный токен, не игровой.

```bash
curl -H "admin-token: $TOKEN" https://figura.serverchichi.online/api/admin/stats
```

```bash
curl -X POST -H "admin-token: $TOKEN" https://figura.serverchichi.online/api/admin/sweep
```

```bash
curl -X POST -H "admin-token: $TOKEN" \
  https://figura.serverchichi.online/api/admin/purge/<uuid>
```

| Маршрут | Что делает |
| --- | --- |
| `GET /api/admin/stats` | сколько игроков, файлов и байт |
| `POST /api/admin/sweep` | прогнать очистку прямо сейчас, не дожидаясь расписания |
| `POST /api/admin/purge/<uuid>` | удалить все аватары игрока и его профиль |
| `GET /api/admin/logs?since=N` | последние строки лога после `N`; `since=0` — хвост |

## Логи в консоли Minecraft-сервера

Чтобы не лазить на хост за `docker logs`, плагин FiguraLink умеет забирать логи
бэкенда и печатать их у себя с префиксом `[backend]`. В его конфиге:

```yaml
backend-logs:
  enabled: true
  admin-token: "<то же, что FIGURA_ADMIN_TOKEN>"
  poll-seconds: 5
  filter: []          # например ["[equip]", "[cleanup]"] — если включён FIGURA_DEBUG
```

Плюс `/figuralink logs [сколько]` — показать хвост по требованию.

Работает это так: бэкенд держит последние `FIGURA_LOG_BUFFER_LINES` строк в
кольцевом буфере с монотонными номерами, плагин помнит номер последней
показанной и просит всё, что после неё. Пропущенный опрос догоняет, повторный
не печатает одно и то же дважды.

Оговорка: это **единственное** место, где плагин ходит к бэкенду по сети. Оно
необязательное и одностороннее — если бэкенд недоступен, зеркало ругнётся один
раз и замолчит, а выдача токенов продолжит работать.

Удаление идёт через сервис, а не по файлам мимо него, — иначе останутся
устаревшие кэши хэшей и подписчики не узнают, что аватар пропал.

## Проверка

Клиент Figura не нужен: токены stateless, поэтому тесты подделывают их по
секрету и гоняют весь протокол. Скрипты лежат в `tools/`:

```bash
python tools/apitest.py <secret> 8080
```

```bash
python tools/wstest.py <secret> 8080
```

Вторым аргументом — порт. Обе проверки на чистом Python, без зависимостей.

Токен, подписанный Java-плагином, можно получить и вручную:

```bash
java -cp FiguraLink-1.0.0.jar dev.figura.link.Tokens <secret> <uuid> <ник> 512000
```

## Что реализовано из протокола backend2

HTTP, база `https://<адрес>/api`:

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/auth/id?username=`, `/auth/verify?id=` | резервный путь через Mojang для немодифицированных клиентов |
| GET | `/` | проверка токена |
| GET | `/limits` | лимиты и скорости — то, что заменяет 100 КБ |
| GET | `/version`, `/motd` | версия и сообщение в гардеробе |
| GET | `/<uuid>` | профиль: надетые аватары и значки |
| GET | `/<owner>/<id>` | байты аватара |
| PUT | `/<id>` | загрузка |
| DELETE | `/<id>` | удаление |
| POST | `/equip` | надеть аватар |
| GET | `/assets/<version>[/<путь>]` | ресурсы Figura, проксируются с официального бэкенда и кэшируются |

WebSocket `wss://<адрес>/ws`, бинарные кадры. C2S: `TOKEN=0, PING=1, SUB=2,
UNSUB=3`. S2C: `AUTH=0, PING=1, EVENT=2, TOAST=3, CHAT=4, NOTICE=5`. Пинги Lua
ретранслируются подписчикам, `EVENT` рассылается при смене аватара.

## Формат токена

Должен совпадать с `Tokens.java` в плагине байт в байт:

```
токен   = base64url(payload) + "." + base64url(hmacSha256(secret, payload))
payload = uuid US ник US expiresAt US maxAvatarSize US maxAvatars
               US uploadRate US downloadRate US pingRateLimit US pingSizeLimit
```

`US` — символ U+001F, `expiresAt` — миллисекунды epoch.

## Ограничения

* Токены нельзя отозвать до истечения срока. Не ставьте TTL в неделю.
* Значки (`pride`/`special`) хранятся, но выдавать их пока нечем — в профиле
  пустые массивы, если не править `users/<uuid>.json` руками.
* `unequipAll` после удаления аватара проходит только по профилям в памяти;
  на выдачу это не влияет — записи с отсутствующим аватаром просто не попадают
  в ответ.
