# figura-backend

Свой бэкенд Figura отдельным сервисом в Docker. Node 22, TypeScript, одна
runtime-зависимость (`ws`).

Даёт то, чего нет у официального бэкенда:

* **аватары работают у игроков без лицензии** — личность подтверждается входом
  на Minecraft-сервер, а не сессионным сервером Mojang;
* **лимит веса аватара задаётся вами** вместо жёстких 100 КБ;
* всё хранится у вас, ни один аватар не уходит на сторонний сервис;
* бэкенд переживает рестарты игрового сервера.

## Из чего состоит система

```
FiguraLink (плагин Paper)              figura-backend (этот сервис)
──────────────────────────             ────────────────────────────
игрок зашёл и прошёл nLogin            /api/*  и  /ws на одном порту
  ↓                                    аватары, профили, кэш ресурсов
подписать HMAC-токен  ─── общий ────→  проверить подпись
отправить figura:backend    секрет     лимиты читаются прямо из токена
```

Плюс **форк клиента SCHFigura** — без него обычная Figura для пиратки не
работает в принципе: она требует ответа сессионного сервера Mojang и отбрасывает
offline-UUID.

Между плагином и сервисом нет ни базы, ни сети, ни требований к порядку
запуска — только совпадающий секрет.

## Запуск

```bash
cp .env.example .env
```

Заполнить `FIGURA_SECRET` — то же значение, что в `config.yml` плагина
FiguraLink. Затем:

```bash
docker compose up -d --build
```

Сервис слушает `127.0.0.1:8080`. Наружу его выставляет reverse proxy, потому что
клиент Figura ходит **только** по `https://` и `wss://` — схема зашита в код мода,
самоподписанный сертификат тоже не подойдёт.

Пример nginx лежит в репозитории плагина (`nginx.conf.example`). Ключевое:
`/api/` и `/ws` идут на один и тот же порт, а на `/ws` нужны заголовки
`Upgrade`/`Connection` и большой `proxy_read_timeout`.

## Настройки

Все через переменные окружения, полный список с комментариями — в `.env.example`.
Что стоит понимать:

| Переменная | Смысл |
| --- | --- |
| `FIGURA_SECRET` | обязательная; общий секрет с плагином |
| `FIGURA_DATA_DIR` | аватары, профили, кэш ресурсов; volume из compose |
| `FIGURA_MAX_AVATAR_SIZE_CEILING` | **не** рабочий лимит, а предохранитель |
| `FIGURA_VERSION_RELEASE` | должна совпадать с `mod_version` форка |
| `FIGURA_WS_KEEPALIVE_SECONDS` | за Cloudflare не выключать |

**Лимит веса аватара задаётся в плагине, а не здесь.** Он подписывается внутрь
токена, потому что только плагин знает про группы прав. Переменная выше — потолок
на случай сломанного или устаревшего плагина; ставьте её заметно выше и забудьте.

## Проверка

Клиент Figura не нужен: токены stateless, поэтому тесты подделывают их по
секрету и гоняют весь протокол. Скрипты лежат в `tools/`:

```bash
python tools/apitest.py <secret> 8080
```

```bash
python tools/wstest.py <secret> 8080
```

Вторым аргументом — порт. Обе проверки на чистом Python, без зависимостей.

Токен, подписанный Java-плагином, можно получить и вручную:

```bash
java -cp FiguraLink-1.0.0.jar dev.figura.link.Tokens <secret> <uuid> <ник> 512000
```

## Что реализовано из протокола backend2

HTTP, база `https://<адрес>/api`:

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/auth/id?username=`, `/auth/verify?id=` | резервный путь через Mojang для немодифицированных клиентов |
| GET | `/` | проверка токена |
| GET | `/limits` | лимиты и скорости — то, что заменяет 100 КБ |
| GET | `/version`, `/motd` | версия и сообщение в гардеробе |
| GET | `/<uuid>` | профиль: надетые аватары и значки |
| GET | `/<owner>/<id>` | байты аватара |
| PUT | `/<id>` | загрузка |
| DELETE | `/<id>` | удаление |
| POST | `/equip` | надеть аватар |
| GET | `/assets/<version>[/<путь>]` | ресурсы Figura, проксируются с официального бэкенда и кэшируются |

WebSocket `wss://<адрес>/ws`, бинарные кадры. C2S: `TOKEN=0, PING=1, SUB=2,
UNSUB=3`. S2C: `AUTH=0, PING=1, EVENT=2, TOAST=3, CHAT=4, NOTICE=5`. Пинги Lua
ретранслируются подписчикам, `EVENT` рассылается при смене аватара.

## Формат токена

Должен совпадать с `Tokens.java` в плагине байт в байт:

```
токен   = base64url(payload) + "." + base64url(hmacSha256(secret, payload))
payload = uuid US ник US expiresAt US maxAvatarSize US maxAvatars
               US uploadRate US downloadRate US pingRateLimit US pingSizeLimit
```

`US` — символ U+001F, `expiresAt` — миллисекунды epoch.

## Ограничения

* Токены нельзя отозвать до истечения срока. Не ставьте TTL в неделю.
* Значки (`pride`/`special`) хранятся, но выдавать их пока нечем — в профиле
  пустые массивы, если не править `users/<uuid>.json` руками.
* `unequipAll` после удаления аватара проходит только по профилям в памяти;
  на выдачу это не влияет — записи с отсутствующим аватаром просто не попадают
  в ответ.
